<Text variant="heading-default-xl">
Когато SEO плъгинът започне да създава credentials за AI агент
</Text>

<Text variant="body-default-l">
В края на август 2026 г. Rank Math се оказа в центъра на security спор, който на пръв поглед изглежда като поредния скандал около WordPress plugin. При по-внимателен технически прочит обаче случаят е много по-интересен: той поставя въпроса какво означава да дадеш на AI агент идентичност в production система.
</Text>

<Text variant="body-default-l">
Версия 1.0.277 на Rank Math въведе нов <strong>Support Agent</strong>, предназначен да подпомага потребителите директно през WordPress администрацията. Малко след това security researcher-ът Sybre Waaijer публикува анализ на начина, по който функционалността използва WordPress Application Passwords. След публичния спор Rank Math пусна версия 1.0.277.2, която временно спира Support Agent-а, докато бъде добавена повече прозрачност около начина, по който се иска достъп до сайта.
</Text>

<h2 id="incident">Какво точно се случи?</h2>

<Text variant="body-default-l">
Според публичния анализ на Sybre Waaijer, Rank Math 1.0.277 съдържа механизъм за създаване на WordPress Application Password, свързан с текущия WordPress потребител. Анализът посочва конкретен кодов път във файла <code>vendor/groupone/wap-client/includes/class-app-password-manager.php</code>.
</Text>

<Text variant="body-default-l">
Това е важно, защото Application Password не е самостоятелна sandboxed identity. Той е credential, асоцииран с конкретен WordPress user.
</Text>

<CodeBlock
code={`WordPress User
      ↓
Application Password
      ↓
Authentication as that user
      ↓
User capabilities`}
language="text"
/>

<Text variant="body-default-l">
Следователно ако credential-ът е свързан с Administrator, security model-ът е фундаментално различен от този при отделен read-only service account.
</Text>

<h2 id="consent">Consent е центърът на спора</h2>

<Text variant="body-default-l">
Най-същественият въпрос не е дали Rank Math е използвал Application Password. Въпросът е <strong>кога</strong> е създаден credential-ът и <strong>кога</strong> потребителят е получил възможност да разбере и разреши това действие.

<Text variant="body-default-l">

<h3 id="architectural">Модел B: „Няма техническа възможност да използва повече права“</h3>

<BlockQuote

<h2 id="rank-math-response">Какво направи Rank Math?</h2>

<Text variant="body-default-l">
Rank Math пусна версия <strong>1.0.277.2</strong> на 31 август 2026 г. с изрично отбелязване, че Support Agent е временно спрян, докато бъде добавена повече прозрачност около начина, по който функционалността иска site access.
</Text>

<Text variant="body-default-l">
Това е важна реакция от security perspective. Vendor-ът не продължава функционалността непроменена, а поставя access mechanism-а на пауза и признава необходимостта от по-ясен flow.
</Text>

<h2 id="separate-vulnerability">Има и отделен Rank Math security проблем</h2>

<Text variant="body-default-l">
Контекстът е още по-интересен, защото версия 1.0.277 е свързана и с отделно публикувана vulnerability: <strong>CVE-2026-77786</strong>. Според GitHub Advisory и WPScan версии преди 1.0.277 не са проверявали правилно дали потребителят притежава необходимата WordPress capability при автоматизирани SEO fixes. Това е позволявало Editor role потребители да променят определени site-wide WordPress настройки, които по принцип са запазени за administrators.
</Text>

<Text variant="body-default-l">
Това е отделна vulnerability и не трябва да бъде смесвана със спора около Support Agent-а.
</Text>

<h2 id="what-admins">Какво трябва да направят WordPress администраторите?</h2>

<Text variant="body-default-l">
Ако управлявате WordPress сайтове с Rank Math, разумният подход е defensive review, а не паника.
</Text>

<h3>1. Проверете версията</h3>

<Text variant="body-default-l">
Rank Math вече е публикувал 1.0.277.2, която временно спира Support Agent функционалността.
</Text>

<h3>2. Проверете Application Passwords</h3>

<CodeBlock
code={`WP Admin
→ Users
→ Profile
→ Application Passwords`}
language="text"
/>

<Text variant="body-default-l">
Публичният анализ посочва credential с име <code>WAP - Rank Math Support Agent</code>. Ако такъв credential съществува, прегледайте го и го revoke-нете, ако не е необходим.
</Text>

<h3>3. Проверете audit/security logs</h3>

<Text variant="body-default-l">
Потърсете необичайна административна активност, промени в user roles, нови credentials, plugin changes и други действия около момента на създаване на Application Password-а.
</Text>

<h3>4. Не бъркайте credential с compromise</h3>

<Text variant="body-default-l">
Наличието на Application Password не доказва, че сайтът е бил компрометиран. То доказва, че трябва да разберете как е създаден credential-ът, за какво е предназначен и дали все още е активен.
</Text>

<h2 id="dictionary">Речник</h2>

<AccordionGroup>

<Accordion title="Application Password">
WordPress credential, предназначен за удостоверяване на приложения и интеграции като конкретен WordPress user.
</Accordion>

<Accordion title="AI Agent">
Софтуерна система, която може не само да генерира отговори, но и да изпълнява действия чрез предоставени инструменти и permissions.
</Accordion>

<Accordion title="Authentication">
Процесът, чрез който системата установява кой user или system използва даден credential.
</Accordion>

<Accordion title="Authorization">
Процесът, чрез който се определя какво може да прави вече удостовереният user или system.
</Accordion>

<Accordion title="Least Privilege">
Security принцип, според който дадена система получава само минималните права, необходими за конкретната задача.
</Accordion>

<Accordion title="Credential Delegation">
Предоставяне на identity или credential на друга система, която може да действа от името на първоначалния user.
</Accordion>

<Accordion title="Trust Boundary">
Граница между системи, при която едната система започва да се доверява на другата.
</Accordion>

<Accordion title="Supply-chain Security">
Защита срещу рискове, произтичащи от външни dependencies, vendors, libraries, APIs и services.
</Accordion>

</AccordionGroup>
